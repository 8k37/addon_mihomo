# Home Assistant Add-on: Mihomo (Clash Meta)

Аддон для Home Assistant, запускающий ядро [mihomo](https://github.com/MetaCubeX/mihomo) (Clash Meta) v1.19.34.

Поддерживаемые архитектуры: `aarch64` (**Raspberry Pi 5**), `amd64`, `armv7`, `armhf`, `i386`.

## Порты

| Порт | Назначение |
|------|------------|
| 7890 | HTTP + SOCKS5 (mixed) прокси |
| 7891 | SOCKS5 прокси |
| 9090 | Внешний контроллер — API / Web UI (метабокс, yacd, zashboard) |

## Установка (Raspberry Pi 5 / HAOS)

### Вариант 1 — локальная папка

1. Скопируйте папку `mihomo` на устройство с HA, например через Samba-шару `addons`:
   ```
   //homeassistant/addons/local/mihomo
   ```
   (на хосте HAOS путь: `/usr/share/hassio/addons/local/mihomo`).
2. В Home Assistant: **Настройки → Дополнения → Магазин дополнений → ⋮ → Проверить обновления**.
3. Появится аддон **Mihomo** (секция "Local add-ons") → **Установить** → **Запустить**.

### Вариант 2 — GitHub-репозиторий

1. Загрузите эту папку в репозиторий GitHub.
2. **Настройки → Дополнения → Магазин → ⋮ → Репозитории** → добавьте URL репозитория.
3. Установите аддон из магазина.

## Настройка

Конфиг хранится в `/share/mihomo/config.yaml` (Samba-шара `share`, папка `mihomo`).

- При первом запуске аддон создаёт базовый конфиг-заготовку.
- Отредактируйте его: добавьте свои `proxies`, `proxy-groups` и `rules`, затем перезапустите аддон.
- В настройках аддона можно изменить путь к конфигу (опция `config_file`), например `/share/mihomo/sub.yaml` для конфига из подписки.

## Панель управления

Ссылки на UI доступны прямо в интерфейсе Home Assistant:

- **Боковая панель** — иконка «Mihomo» (щит) в меню слева; открывает панель через Ingress, извне проброс портов не нужен.
- **Кнопка «Открыть веб-интерфейс»** на странице аддона (Настройки → Дополнения → Mihomo).
- Напрямую: `http://<ip-хоста>:9090/ui`.

При первом открытии metacubexd попросит указать backend:
- при входе через панель HA укажите адрес текущей страницы ingress без `ui/` на конце (виден в адресной строке), например `http://homeassistant.local:8123/api/hassio_ingress/<token>`;
- при прямом доступе — `http://<ip-хоста>:9090`.

Если в конфиге задан `secret`, введите его при добавлении backend.

## Использование прокси

На устройствах в локальной сети укажите прокси:

- HTTP: `<ip-hass>:7890`
- SOCKS5: `<ip-hass>:7890` или `:7891`

## Выбор узла: как это работает

Аддон создаёт две стандартные группы (ваши собственные группы не трогаются и идут после них):

| Группа | Роль |
|---|---|
| **PROXY** | Точка входа: селектор всех узлов, по умолчанию указывает на AUTO. Можно вручную закрепить любой узел в панели |
| **AUTO** | url-test: сам выбирает самый быстрый по пингу узел (проход каждые 5 мин) |

Вся логика выбора — штатная логика mihomo, без дополнительных служб. Смена узла: вручную в панели (PROXY) или автоматически по пингу (AUTO).

## Режим работы и режим шлюза

- **`mode`** — `global` (по умолчанию; весь трафик через VPN) / `rule` / `direct`. В глобальном режиме аддон сам направляет встроенную группу GLOBAL на PROXY.
- **`gateway_mode`** — прозрачный прокси для других устройств (см. ниже).

## Подписки и VPN-узлы

В настройках аддона два списка:

- **`subscriptions`** — URL подписок в формате Clash/mihomo (YAML). Можно указать несколько — аддон создаёт по ним `proxy-providers` (`sub1`, `sub2`, ...), ядро само скачивает и обновляет их раз в 6 часов. При удалении подписки из настроек она (и её кэш) автоматически убирается из конфига.
- **`vpns`** — конкретные VPN/прокси-узлы, каждый элемент списка — определение одного прокси в YAML или JSON, например:
  ```yaml
  {"name": "my-vpn", "type": "ss", "server": "vpn.example.com", "port": 443, "cipher": "aes-256-gcm", "password": "secret"}
  ```

Группы PROXY/AUTO создаются автоматически и пересобираются при каждом старте. Если вы ведёте свои группы в конфиге, добавьте в них `use: [sub1, sub2, vpns]`.

## Режим шлюза (NAT-маршрутизация)

В настройках аддона есть опция **`gateway_mode`**. При включении хост с Home Assistant может работать как узел NAT-маршрутизации: устройства, у которых указаны **шлюз и DNS = IP этого хоста**, пойдут через mihomo.

Как это работает:

- TCP-трафик перехватывается через iptables REDIRECT и заворачивается в mihomo (`redir-port: 7893`), применяются ваши `rules`.
- DNS (udp/tcp 53) перехватывается на встроенный DNS mihomo (порт 1053, `redir-host`).
- Локальные сети (RFC1918, multicast и т.п.) не перехватываются.
- UDP (кроме DNS) и IPv6 не проксируются — идут напрямую через маршрутизацию.
- Правила iptables снимаются при остановке аддона.

Требования и ограничения:

- Аддон использует `host_network: true` и привилегию `NET_ADMIN` (нужны для iptables/перехвата).
- Работает по IPv4 в одной L2-сети с клиентами.
- Если HA-хост станет недоступен как шлюз — клиенты потеряют интернет, поэтому не указывайте его шлюзом по умолчанию на роутере, не убедившись, что всё работает.
- Аддон должен быть запущен до того, как клиенты начнут его использовать.

## Примечания

- При первом запуске mihomo сам скачивает `geoip.metadb` в папку конфига — нужен доступ в интернет.
- Режим TUN (прозрачный VPN для всей системы) требует `host_network` и privileged-доступа; в базовой версии аддона не включён — используйте прокси на портах 7890/7891.
- Рекомендуется задать `secret` в конфиге для панели управления на порту 9090.
